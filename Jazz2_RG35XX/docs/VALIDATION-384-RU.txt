Jazz2 RG35XX 1.1.2 — испытания оптимизации 384x288
28 ноября 2026. Протокол испытаний перед выпуском релиза.

Область изменения
Кандидат сохраняет оптимизации 320x240 из предыдущей тестовой сборки 1.1.2 и добавляет отдельный NEON-путь только для ширины 384. Алгоритмы 304, 480 и 640 не оптимизировались.
В 384x288 предварительно рассчитываются индексы выбора байтов. Каждые восемь выходных RGB565 пикселей формируются инструкциями NEON table lookup. При 32-битном выводе преобразование каналов выполняется сразу, без промежуточной скалярной конвертации 640 пикселей. Особый последний блок не читает за правым краем исходной строки.
Соответствие пикселей осталось точным: floor(x*384/640), с прежней вертикальной ориентацией и масштабированием. Сглаживание, эффекты и качество изображения не менялись.

Микробенчмарк на приставке
384x288 -> 640x480, по 5 секунд на прогон, порядок база–оптимизация–оптимизация–база.
Штатная максимальная частота 1008 МГц, governor performance временно; без разгона.
16-битный framebuffer:
  база: 562.7 и 563.4 операций/с;
  NEON: 1348.0 и 1350.0 операций/с;
  примерно 2.40 раза быстрее, 1.78 -> 0.74 мс на вывод.
32-битный framebuffer:
  база: 229.2 и 230.9 операций/с;
  NEON: 584.0 и 583.9 операций/с;
  примерно 2.54 раза быстрее, 4.35 -> 1.71 мс на вывод.
Это ускорение вывода, а не всей игры.

Игровое сравнение
Сцена: сохранение Hare Scare, flash/06_medivo2, из предыдущего изолированного стенда. Все прогоны начинались с одной копии сохранения без управления игроком. Внутреннее разрешение 384x288, лимит 60 FPS. По 30 секунд на прогон, первое пятисекундное окно загрузки исключено.
В каждом режиме framebuffer порядок база–оптимизация–оптимизация–база. База — предыдущий кандидат 1.1.2 с оптимизацией 320 и старым выводом 384. Число потоков рендера осталось три. Частота по всем собранным отсчётам 1008000 кГц.
Средние результаты:

32 бита: 34.673 -> 37.400 FPS (+7.86%).

Почему скорость ниже, чем в 320x240
384x288 содержит на 44% больше внутренних пикселей, чем 320x240. Стоимость программного рендера остаётся существенной; оптимизация вывода не обеспечивает стабильные 45/60 FPS на этой сложной сцене при 1008 МГц. Другие сцены, частоты и траектория игрока дадут другие результаты.

Корректность и проверки
- Побайтовые проверки 384x288 для framebuffer 16/32 bpp, RGB/BGR, альфа, padding и смещений.
- Все 65536 RGB565 цветов, 54 случая раскладок/смещений для 384x288.
- Каждая исходная строка теста заканчивается у недоступной страницы памяти: чтение за строкой привело бы к падению. Все проверки прошли.
- Регрессионные проверки прежних путей 304 и 320, включая цвета и границы записи.
- ABI/Cortex-A9, memset, музыка menu.j2b, intro, уровень, сохранение настроек, штатный выход MENU; ожидаемый отказ для 24 bpp.
- Отдельный запуск игры в QEMU с настоящим внутренним разрешением 384x288 и 32-битной моделью GarlicOS: меняющиеся кадры, запись настроек, MENU exit=0.
- Все восемь аппаратных прогонов завершились с кодом 0. Сообщений XRUN/underrun в этих журналах нет. Проверка на слух не проводилась.
- Приложены снимок реального экрана и снимок QEMU.
- SDK Miyoo GCC 7.3.0, Cortex-A9/NEON/softfp, O2. В бинарнике нет диагностических режимов остановки вывода или выбора числа потоков.

Сохранность среды
Игры запускались из /mnt/SDCARD/.jazz2-384, с отдельными Saves. Основная установка на карте не заменялась. По завершении восстановлены исходный framebuffer и governor interactive. Исходные клоны репозиториев не изменялись.

Как проверить кандидат
Сохраните резервную копию установленного jazz2. Замените только Roms/PORTS/Jazz Jackrabbit 2/jazz2 файлом из update ZIP. Не удаляйте Saves.
В игре выберите 384x288 в настройках графики, выйдите по MENU и перезапустите игру. Для сравнения выберите тот же лимит FPS, что использовали раньше.
Настройки по умолчанию остаются 320x240 / 45 FPS. После установки текущие пользовательские настройки сохраняются. Предыдущая оптимизация 320x240 также включена.
Для отката верните прежний бинарник.
Личный ready-to-play содержит предоставленные владельцем игровые ресурсы; он не предназначен для публикации. В source-архиве игровых ресурсов и SDK нет.

Границы выводов
Тесты одной сохранённой сцены и функциональные проверки не заменяют прохождение всех уровней. Средние FPS получены по пятисекундным окнам; задержки каждого отдельного кадра здесь не измерялись. Результаты микробенчмарка нельзя переносить на ускорение всей игры.
