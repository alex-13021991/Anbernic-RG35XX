Jazz2 RG35XX 1.1.1 — доработка и испытания, 28 ноября 2026

Изменения
1. На RG35XX пустое имя и стандартное имя root заменяются на RG35XX при создании нового результата. Сохранённое пользовательское имя сохраняется. Ранее записанные строки таблицы результатов не переписываются.
2. Масштабирование 320 -> 640 пикселей ускорено NEON: за один проход дублируются восемь RGB565 пикселей. Другие разрешения используют прежний общий алгоритм. Цвета, вертикальная ориентация, шаг строки и смещения экрана проверены побайтово.
3. scripts/release.py получает номер версии из VERSION.

Приставка и методика
Оригинальная RG35XX / GarlicOS, Cortex-A9, online CPU 0-3, governor interactive. Частота автоматически менялась; governor, частоты, системные библиотеки и прошивка не изменялись. Тестовая установка: /mnt/SDCARD/.jazz2-tuning, отдельные сохранения. Меню временно приостанавливалось на время замеров и возобновлено после них.
ARM: Miyoo GCC 7.3.0, Cortex-A9, NEON, softfp, O2, без LTO.

Производительность
Все замеры игры: 320x240 -> 640x480, лимит 60 FPS. Средние по пятисекундным окнам после первого окна загрузки:
- 1.1.0, prince/01_castle1, 35 с: 59.62 FPS, диапазон 59.50–59.69.
- 1.1.1, prince/01_castle1, 35 с: 59.68 FPS, диапазон 59.58–59.73.
- 1.1.1, flash/01_diam1, 65 с: 59.56 FPS, диапазон 59.40–59.68.
Первое окно включает загрузку и даёт около 42 FPS; это не устойчивый игровой FPS.
На железе наблюдались 7 потоков процесса и выполнение на всех четырёх ядрах. Рендерер уже создаёт три рабочих потока, главный поток также обрабатывает тайлы; декодирование музыки вынесено отдельно. Добавлять потоки без основания не потребовалось.
Микробенчмарк вывода framebuffer, 320x228 -> 640x480, по 5 с, порядок ABBA:
база 687.8; NEON 2269.5; NEON 2263.1; база 687.5 операций/с.
Ускорение данного этапа около 3.3 раза, НЕ ускорение всей игры в 3.3 раза. Это примерно 1.45 -> 0.44 мс на вызов при условиях этого теста. Governor был interactive, частота на границах прогонов 240–1008 МГц; результат не является сравнением при фиксированной частоте.
Настройки по умолчанию оставлены 320x240 / 45 FPS. Замеры при 60 показывают возможность выбирать 60 для проверенных сцен.

Звук
OpenAL Soft использует ALSA plughw:0,0, встроенный ATC2603C. Запрошено и подтверждено OpenAL: stereo Signed Short 44100 Hz, 1024 frames x3. ALSA hardware: S32_LE, 2 channels, 44100 Hz, состояние RUNNING, продвигаются hw_ptr/appl_ptr. Разница S16 игры и S32 железа соответствует преобразованию plughw; сама по себе не является ошибкой.
За прогоны ошибок XRUN/underrun и сообщений восстановления OpenAL не зафиксировано. Декодирование menu.j2b даёт ненулевой сигнал: 4096 кадров, peak 12019. Маршрут и частота корректны по программным данным. Акустическое качество динамика, искажения и баланс каналов на слух дистанционно не проверены; непрерывный звук во всех игровых ситуациях не гарантируется этими короткими тестами. Настройки звука и библиотеки не менялись.

QEMU и функциональные проверки
- ABI и динамические зависимости; нет инструкций вне Cortex-A9 из проверяемого списка.
- Исправление memset.
- Framebuffer 16/32 bpp, RGB и BGR, смещения страниц и padding; проверка каждого пикселя.
- Дополнительно те же шесть проверок для нового NEON пути ширины 320.
- intro, prince/01_castle1, 16 bpp, padded 32 bpp: меняющиеся кадры, сохранение настроек, выход MENU 0.
- Неподдерживаемый 24 bpp: ожидаемый отказ, код 1.
- Game Over: отдельный диагностический бинарник после 180 кадров устанавливает последнюю жизнь и вызывает штатный TakeDamage. Затем выполняется обычный путь смерти -> результаты. С именем root таблица получает RG35XX; с именем Alex сохраняется Alex. Сделаны скриншоты. Диагностические хуки не входят в релизный ELF; их строки в нём отсутствуют.

Границы испытаний
Это автоматические запуски начальных сцен двух уровней, а не прохождение всей игры. Не проверены все боссы, длительные сессии, все сочетания настроек и субъективное качество звука. QEMU использовался для функциональных проверок и скриншотов, не для измерения скорости приставки.

Установка
Сначала сохранить резервную копию текущей папки игры и Saves. Распаковать Roms из ready-to-play ZIP в корень карты с заменой файлов. Saves из архива не добавляются; существующие сохранения остаются на карте. Для применения текущих изменений достаточно заменить jazz2.
На приставке основная установленная игра не заменена: новая сборка запускалась только из отдельной тестовой папки.
Ready-to-play содержит ресурсы из личного входного архива: это личный комплект владельца, не для публичной публикации. Source-архив содержит код порта, патчи и vendor-зависимости, без игровых ресурсов и без SDK. SDK уже установлен по указанному владельцем пути.

Рабочая копия: /home/alex/RG35XX/Work/jazz2-tuning
Сборка: export RG_TOOLCHAIN=$HOME/RG35XX/RG35XX-SDK/miyoo-gcc-7.3.0
         export JAZZ2_WORK=$HOME/RG35XX/Work/jazz2-1.1.1-clean
         bash scripts/prepare.sh
         bash scripts/build.sh
Проверки: bash scripts/verify.sh /путь/к/Content
Дополнительные проверки NEON: собрать tests/video.cpp с -DTEST_VIDEO_WIDTH=320 в $JAZZ2_WORK/tests/video320, затем TEST_VIDEO_WIDTH=320 python3 tests/framebuffer.py "$JAZZ2_WORK".

При испытаниях исходные клоны не изменялись. Для публикации версии 1.1.1 подготовлена отдельная копия репозитория. ADB 34.0.4 установлен в Ubuntu; USB-тесты выполнялись через Windows ADB, вызываемый из WSL.
