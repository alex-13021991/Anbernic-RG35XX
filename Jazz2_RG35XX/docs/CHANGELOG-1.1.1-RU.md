# Jazz² Resurrection для RG35XX — 1.1.1

Обновление порта Jazz Jackrabbit 2 / The Secret Files для **оригинальной RG35XX (2022), GarlicOS 1.4.9**. Движок — Jazz² Resurrection 3.7.0.

## Имя игрока в таблице результатов

В новых результатах после потери последней жизни вместо системного имени `root` используется **RG35XX**. Исправление также работает, если стандартное `root` уже сохранено в настройках. Пользовательские имена, например `Alex`, сохраняются. Ранее записанные строки таблицы не переименовываются.

В QEMU проверен штатный переход после смерти персонажа в таблицу результатов. Для воспроизводимости отдельный диагностический бинарник устанавливал последнюю жизнь и вызывал обычный обработчик урона. Проверены оба случая: `root → RG35XX` и `Alex → Alex`. Диагностические хуки в релизный бинарник не входят.

## Оптимизация вывода изображения

Добавлен NEON-путь для точного горизонтального масштабирования **320→640**: восемь RGB565 пикселей загружаются и дублируются векторными операциями. Остальные размеры обрабатываются общим алгоритмом.

На реальном framebuffer отдельный пятисекундный микробенчмарк в порядке «база — NEON — NEON — база» дал:

| Вариант | Операций вывода/с |
|---|---:|
| Базовый, первый прогон | 687,8 |
| NEON, первый прогон | 2269,5 |
| NEON, второй прогон | 2263,1 |
| Базовый, второй прогон | 687,5 |

Ускорение **данного этапа** — около **3,3 раза**, а не всей игры. Проверки каждого пикселя прошли для 16/32 bpp, RGB/BGR, смещений экрана и дополнительного шага строки. Governor оставался `interactive`, частота менялась автоматически; это не сравнение при фиксированной частоте CPU.

## Многопоточность и производительность на приставке

Рендерер уже использует три рабочих потока, главный поток также обрабатывает тайлы. Декодирование музыки выполняется отдельно. На приставке наблюдались **семь потоков процесса** и выполнение на **всех четырёх ядрах**. Дополнительные потоки без подтверждённой необходимости не добавлялись.

Измерения при **320×240 → 640×480, лимит 60 FPS**, среднее по пятисекундным окнам после окна загрузки:

| Версия | Уровень | Длительность | Средний FPS |
|---|---|---:|---:|
| 1.1.0 | prince/01_castle1 | 35 с | 59,62 |
| 1.1.1 | prince/01_castle1 | 35 с | 59,68 |
| 1.1.1 | flash/01_diam1 | 65 с | 59,56 |

Первое окно включает загрузку и даёт около 42 FPS. Существенного роста общего FPS при уже достигнутом лимите 60 не ожидается: изменение уменьшает затраты на масштабирование.

По умолчанию остаются **320×240 / 45 FPS**, меню — **30 FPS**. Игровой лимит можно выбрать в настройках.

## Проверка звука

Подтверждён вывод через **OpenAL Soft → ALSA `plughw:0,0` → встроенный ATC2603C**:
- OpenAL: стерео, Signed Short, **44 100 Гц**, буфер 1024 кадра × 3;
- аппаратный PCM: **S32_LE, два канала, 44 100 Гц**, состояние RUNNING, указатели воспроизведения продвигаются;
- разница S16 приложения и S32 аппаратного PCM соответствует преобразованию через `plughw`;
- за эти прогоны сообщений XRUN/underrun и восстановления OpenAL не обнаружено;
- декодирование `menu.j2b` выдаёт ненулевой сигнал: 4096 кадров, peak 12019.

Звуковые библиотеки и настройки не менялись. Акустическое качество динамика, баланс каналов и искажения на слух дистанционно не проверялись.

## Остальные проверки

Сборка выполнена в WSL Ubuntu 24.04: **Miyoo GCC 7.3.0, Cortex-A9, NEON, softfp, O2, без LTO**.

Проверены ABI и зависимости, отсутствие проверяемых инструкций вне Cortex-A9, memset, framebuffer, обработка кнопок, музыка, меняющиеся кадры, запись настроек и выход по MENU. Запуски QEMU охватывают intro, первый уровень, 16 bpp и 32 bpp с padding. Для неподдерживаемого 24 bpp подтверждён ожидаемый отказ. Итоговое дерево воспроизводится из vendor-архивов и патчей; чистая пересборка побайтно совпала с испытанным релизным ELF.

Это автоматические тесты начальных сцен двух уровней, а не прохождение всей игры. Боссы, продолжительные игровые сессии и все сочетания настроек не проверены. Скорость измерялась на приставке, QEMU использовался для функциональных проверок.

## Установка и файлы

Перед обновлением сохраните резервную копию папки игры и `Saves`.

1. Распакуйте `Roms` из **Jazz2_RG35XX_v1.1.1.zip** в корень карты с заменой файлов.
2. Сохраните существующие `Content` и `Saves`; ранее подготовленные ресурсы совместимы.
3. Для первой установки подготовьте свои ресурсы через **Jazz2_RG35XX_Tools_v1.1.1.zip**. Инструкция конвертации включена в комплект.
4. Запустите игру из PORTS.

Файлы:
- **Jazz2_RG35XX_v1.1.1.zip** — игра и необходимые библиотеки, **без игровых данных**.
- **Jazz2_RG35XX_Tools_v1.1.1.zip** — конвертеры Windows/Linux, EngineContent, инструкции и лицензии.
- **Jazz2_RG35XX_v1.1.1-source.tar.gz** — исходники порта, патчи, vendor-зависимости, тесты и документация; SDK доступен в каталоге Toolchains репозитория.
- **VALIDATION-1.1.1-RU.txt** — подробный протокол и ограничения испытаний.
- **SHA256SUMS.txt** — контрольные суммы файлов релиза.

Игровые ресурсы и личный ready-to-play комплект в публичный релиз и исходники не включены. Движок и изменения порта распространяются по GPL-3.0; сторонние компоненты сохраняют свои лицензии.
