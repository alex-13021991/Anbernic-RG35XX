# Jazz² Resurrection для RG35XX — 1.1.2

Обновление порта **Jazz Jackrabbit 2 / The Secret Files** для **оригинальной Anbernic RG35XX (2022) с GarlicOS 1.4.9**. Движок — Jazz² Resurrection 3.7.0.

## Настройки по умолчанию

В бинарнике по-прежнему заданы **320×240 и лимит 45 FPS в игре**, меню — **30 FPS**. Режим 320×240 остаётся основным: на тяжёлой сцене он обеспечивает более комфортную скорость, чем 384×288.

Это подтверждено отдельным запуском итогового бинарника в QEMU с пустой папкой настроек и без аргумента ограничения FPS: внутреннее разрешение 320×240, игровой лимит 45.

**Сохранённые настройки имеют приоритет.** Обновление не сбрасывает выбранные ранее разрешение и FPS. Для возврата выберите 320×240 и 45 FPS в меню; изменение разрешения применяется после выхода по MENU и повторного запуска.

## Что изменилось относительно 1.1.1

### Ускорен 32-битный вывод в режиме 320×240

Преобразование внутреннего RGB565 в 32-битные каналы framebuffer объединено с точным масштабированием 320→640. NEON обрабатывает восемь исходных пикселей за шаг. Для распространённого формата GarlicOS R0/G8/B16 без альфа используется специализация с постоянными позициями каналов; другие допустимые раскладки также поддерживаются.

На сохранённой тяжёлой сцене Hare Scare время вывода кадра уменьшилось примерно **с 3,24 до 2,06 мс**, средняя скорость в сопоставимых прогонах — **с 45,74 до 48,35 FPS (+5,7%)** при лимите 60.

### Добавлена оптимизация режима 384×288

Для растяжения **384→640** добавлен отдельный NEON-путь с предварительно рассчитанными индексами пикселей:
- при 16-битном выводе ускоряется подбор исходных RGB565 пикселей;
- при 32-битном выводе одновременно выполняются масштабирование и преобразование каналов;
- последний блок обрабатывается без чтения за правым краем исходной строки.

Сохраняется прежнее точное соответствие `floor(x×384/640)`, вертикальная ориентация, цвета и изображение. Эффекты и качество не снижались.

В отдельном тесте масштабирования/вывода 384×288:
- **16 бит:** примерно 563 → 1349 операций/с, ускорение этапа **в 2,40 раза**;
- **32 бита:** примерно 230 → 584 операций/с, ускорение этапа **в 2,54 раза**.

Это ускорение конкретного этапа, а не всей игры.

### Результаты на реальной приставке

Сохранённая сцена **Hare Scare, flash/06_medivo2**, штатные **1008 МГц**, лимит **60 FPS** для измерения запаса производительности. После окна загрузки:

| Внутреннее разрешение | Framebuffer | До | После | Изменение |
|---|---|---:|---:|---:|
| 320×240 | 32 бита | 45,74 | 48,35 | +5,7% |
| 384×288 | 16 бит | 38,79 | 40,32 | +3,9% |
| 384×288 | 32 бита | 34,67 | 37,40 | +7,9% |

Каждая строка сравнивает базовый и оптимизированный варианты одинаковым методом. Для 320 использовались сопоставимые диагностические сборки; чистый кандидат отдельно подтвердил около 48,7 FPS. Для 384 — обычные бинарники, по два прогона каждого варианта в порядке база–оптимизация–оптимизация–база, по 30 секунд.

При 384×288 внутренних пикселей на **44% больше**, чем при 320×240. Оптимизация помогает, но не обеспечивает стабильные 45/60 FPS на этой тяжёлой сцене при 1008 МГц. Владелец проверил тестовые сборки и отметил, что играть комфортнее в режиме по умолчанию.

Пути вывода 304×228, 480×360 и 640×480 в этом обновлении не оптимизировались. Оптимизация 16-битного вывода 320×240 из 1.1.1 сохранена.

## Многопоточность и звук

Число рабочих потоков рендера осталось **три**, главный поток также обрабатывает тайлы; декодирование музыки выполняется отдельно. Вариант с двумя рабочими потоками не дал выигрыша среднего FPS на проверенной сцене и в релиз не включён.

Звуковые библиотеки и настройки не менялись. В аппаратных прогонах вывод ALSA работал, сообщений XRUN/underrun не обнаружено. Субъективное качество динамика и баланс каналов на слух дистанционно не оценивались.

## Проверки

- Все **65 536 цветов RGB565**, различные положения RGB/альфа, отсутствие альфа, 16/32 bpp, padding и смещения framebuffer.
- Исходные строки заканчиваются у недоступной страницы памяти: подтверждено отсутствие чтения за правым краем.
- Регрессионные проверки прежних путей 304 и 320, включая границы записи.
- ABI и профиль Cortex-A9, memset, музыка, intro, игровые уровни, сохранение настроек и выход MENU.
- Отдельный запуск игры в QEMU при настоящем внутреннем разрешении **384×288**: меняющиеся кадры, сохранение настроек, MENU exit=0.
- Проверка штатных **320×240 / 45 FPS** на свежих настройках без FPS-аргумента.
- Восемь аппаратных прогонов 384×288 завершились с кодом 0.
- В итоговом ELF отсутствуют диагностические режимы отключения вывода, принудительного продолжения и выбора числа потоков.

Сборка: **Miyoo GCC 7.3.0 / Cortex-A9 / NEON / softfp / O2**, без LTO. Тесты и подробные русские протоколы включены в исходники.

## Установка

1. Сохраните резервную копию папки игры, особенно `Saves`.
2. Распакуйте `Roms` из **Jazz2_RG35XX_v1.1.2.zip** в корень карты с заменой файлов.
3. Сохраните существующие `Content` и `Saves`: ресурсы предыдущих версий совместимы. Для обновления с 1.1.1 достаточно заменить `jazz2`.
4. Для первой установки подготовьте собственные ресурсы через **Jazz2_RG35XX_Tools_v1.1.2.zip**.
5. Запустите игру из PORTS.

Для проверки 384×288 выберите его в настройках графики и перезапустите игру. Для более плавной игры оставьте **320×240 / 45 FPS**.

## Файлы релиза

- **Jazz2_RG35XX_v1.1.2.zip** — установочный комплект игры и библиотек, без игровых данных.
- **Jazz2_RG35XX_Tools_v1.1.2.zip** — конвертеры Windows/Linux, свободные EngineContent, инструкции и лицензии.
- **Jazz2_RG35XX_v1.1.2-source.tar.gz** — код порта, vendor-зависимости, патчи, тесты и документация. SDK доступен в каталоге Toolchains репозитория.
- **VALIDATION-1.1.2-RU.txt** — сводный протокол испытаний и ограничения.
- **SHA256SUMS.txt** — контрольные суммы файлов релиза.

Замеры относятся к конкретной сцене и условиям, а не ко всем уровням. QEMU использовался для функциональных проверок; скорость измерялась на приставке. Пользовательские сохранения, оригинальные игровые ресурсы и личные ready-to-play комплекты не публикуются.
