# Устройство порта
Логический мир остаётся 800×600. LowResScreen проецирует рисование в буфер выбранной ширины; framebuffer масштабирует результат на экран. По умолчанию 640×480. Для 800 используется исходный полный путь. Обработаны прямоугольники, спрайты, отражения, повороты, матрицы, треугольники, кэшированные растения и тени. Кэшированные кадры растений требуют отдельного пути: исходный код записывал пиксели в обход общего API.

Прямой вывод RGB565 устраняет лишнюю загрузку текстуры SDL, RenderCopy и ReadPixels в игре. Backend поддерживает также RGB/BGR 32-битный framebuffer. Исходные параметры системного framebuffer и частота процессора не меняются.

Главный поток CPU0, существующий worker CPU1, аудиопоток CPU2. CPU3 не занят постоянной задачей порта. Маска из двух ядер не делает один поток параллельным. Профиль показал основной расход на наложение изображений (~58% выборок), затем вывод кадра (~14%), поэтому оптимизировался графический путь. Это выборочное профилирование, не точный процент времени всей игры.

SDL dummy используется для программной отрисовки меню. Ввод идёт из evdev RG35XX Gamepad, поддерживается собственное состояние клавиш. Фокус для dummy задан явно. Системный Miyoo watchdog/power restore удалён. Порядок уничтожения текстур и звукового интерфейса исправлен.

Звук: libopenmpt + встроенный SDL-Mixer-X, 44100 Гц stereo, период 2048. Фактическое потребление mono на устройстве оказалось вдвое выше номинала ALSA. Повышение буфера само по себе маскировало пропуски, но не исправляло темп; stereo устраняет причину. Реальное ALSA-окно stereo: period 2048, buffer 4096 (~93 мс при 44100 Гц).

SELECT переключает x1 -> x0.5 -> x2 -> x1. x0.5 выполняет один тик игровой логики на два штатных тика, x2 — два на каждый; ввод и отрисовка продолжают обслуживаться. Это не изменение частоты аудио. Счётчик фазы сбрасывается при переключении. Штатный сброс на x1 при начале/завершении уровня сохранён.
MENU вызывает CloseRequestAsync -> Shutdown -> ShutdownHook -> WriteCurrentUserConfig и Board::TryToSaveGame до удаления аудио/поля. Это тот же метод сохранения поля, что и у выхода через меню; его NeedSaveGame ограничения не обходятся.
